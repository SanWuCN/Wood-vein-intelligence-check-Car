# 环境重置与数据链路检查

本次实测：雷达约10Hz、消息延迟2–10ms；/scan、底盘、EKF各一个发布者，底盘串口仅一个进程占用。未发现重复雷达或底盘服务。

异常状态下连续6秒未收到 /odom、/odom_combined、/imu/data_raw；EKF进程存在但无输入，故无 odom_combined→base_footprint 动态TF，AMCL无法处理扫描，地图无箭头和雷达叠加。底盘驱动打开串口后未输出有效数据。重启驱动链路后里程计/IMU恢复。串口停流的更底层诱因尚未确定，不能保证所有异常已消除。

修改：
- POST /api/control/reset，沿用控制令牌、同源检查、命令串行锁及请求幂等机制。
- 取消并等待旧定位任务，停止运动任务，关闭已管理底盘/雷达/导航进程组，清除旧地图TF/传感器缓存/任务状态，启动待命底盘；不自动加载地图，不开始巡航。
- 建图中重置前自动备份，保留所有已保存地图和路线。
- 等待最多20秒确认底盘、IMU、融合里程计恢复，否则返回503 CHASSIS_OFFLINE，明确提示检查供电/USB，不虚报成功。
- 地图切换也检查底盘数据；失败清理启动进程并回待命。增加旧Nav2容器/规划节点残留检测，有冲突则拒绝启动新进程。
- 无数据不再误报为“小车移动中”；定位变换无效清除旧雷达叠加；任务故障区分底盘、雷达、定位。
- 顶栏“重置”按钮有确认弹窗。
