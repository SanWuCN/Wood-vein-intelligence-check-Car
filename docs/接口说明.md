# 木脉智检 · 小车端接口 v1.0

本项目独立部署在小车，未修改平台源码。生产服务 `http://192.168.31.221:8765`；小车屏幕访问 `http://127.0.0.1:8765`。JSON 使用 UTF-8。以下路径相对服务根地址。接口及 WS 提供真实数据；只有显式 `--simulate` 才使用演示数据，并返回 `simulated:true`。

## 1. 身份与通信

读接口供同一可信局域网的平台访问。所有 POST 和 `GET /api/config` 要求请求头：

```http
Content-Type: application/json
X-Control-Token: <小车 config.local.json 中的 control_token>
X-Request-Id: <本次逻辑操作的唯一编号，建议 UUID>
```

`X-Request-Id` 可选，最多 120 字符。同一编号、路径、请求体重复提交返回第一次成功结果；编号被用于其他内容返回 `409 IDEMPOTENCY_CONFLICT`。仅缓存当前服务进程最近 256 次成功请求，重启不保留。请求超时后先查询状态，再决定是否重试。设置地址和令牌保存在小车 `config.local.json`，权限 0600。

`GET /api/session`：`{token,can_control,device_id,max_speed_mps}`。只有请求实际来自回环地址时返回控制令牌；局域网浏览器默认只读。需要远程操作时可用 SSH 隧道：

```bash
ssh -L 8765:127.0.0.1:8765 wheeltec@192.168.31.221
# 浏览器打开 http://127.0.0.1:8765
```

浏览器 POST/WS 的 Origin 必须与 Host 一致；无跨域 CORS 放行。平台服务器可以用令牌访问控制 API。不要将令牌写进 URL 或平台公开前端包。本服务面向局域网，不应直接开放到公网。

成功操作返回 HTTP 200、`{"ok":true,...}`；查询直接返回资源，不包裹 `data`。失败格式：

```json
{"ok":false,"error":{"code":"POINT_BLOCKED","message":"航点位于障碍物或未知区域"}}
```

HTTP 403 权限/来源问题；404 资源不存在；409 状态冲突；415 请求类型错误；422 参数不合法；503 服务不可用；504 ROS 超时；500 内部错误。`ok:true` 表示该操作已接收或该步骤完成，巡航最终结果必须查看 `mission.state`。

## 2. 状态与数据

| 请求 | 返回 |
|---|---|
| `GET /api/health` | `{ok:true,version:"1.0.0",simulated:false}`，仅代表服务存活 |
| `GET /api/state` | 当前完整状态，结构见下文 |
| `WS /api/ws` | 约 2 Hz 推送 `{type:"state",payload:<完整状态>}`；服务 heartbeat 15 秒 |
| `GET /api/map` | 当前地图元信息；未就绪返回 404 |
| `GET /api/map.png` | 当前栅格地图 PNG；与元信息组合用于交互 |
| `GET /api/maps` | `{maps:[<已保存地图>...]}`，按创建时间倒序 |
| `GET /api/maps/{id}/preview.png` | 已保存地图预览 PNG |
| `GET /api/maps/{id}/files/map.yaml` | Nav2 map_server 配置 |
| `GET /api/maps/{id}/files/map.pgm` | Nav2 地图图像，与 YAML 放在同一目录 |
| `GET /api/maps/{id}/files/metadata.json` | 地图元数据 |
| `GET /api/routes` | `{routes:[<路线>...]}` |
| `GET /api/config` | 连接设置；需要控制令牌，不回传任何令牌值 |

WS 断线后客户端自行退避重连，重新取得完整状态。超过 3 秒没有新状态，应显示断线并禁用运动操作。不能根据视频正在播放判断车辆在线。

完整状态字段：

| 字段 | 类型、单位、含义 |
|---|---|
| `schema_version` / `device_id` | 字符串，当前 `1.0` / `mumai-car-01` |
| `sampled_at` | Unix 秒，状态采样时间 |
| `simulated` | boolean，生产为 false |
| `mode` | `idle`、`mapping`、`navigation` |
| `transition` | null 或正在切换的目标 mode |
| `uptime_s` | 当前模式计时，服务重启也重置 |
| `active_map_id` | 巡航已加载地图 ID；无地图为 null |
| `map` | 元信息或 null，见第 3 节 |
| `pose` | `{x,y,yaw}` 或 null，map 坐标下的 base_footprint 位姿；m、rad |
| `velocity` | `{linear_mps,angular_rps,pose}` 或 null；其中 pose 是 odom_combined 中的里程计位姿，不是 map 位姿 |
| `imu` | 姿态/角速度/加速度对象或 null，见示例 |
| `imu_history` | 最多 90 组 `[unix秒,roll_deg,pitch_deg,yaw_deg]` |
| `lidar` | `{state:"online"或"offline",hz:number或null,age_s:number或null}`；2 秒无扫描则离线 |
| `camera` | `{state,fps,age_s}`；3 秒无新图则离线，fps 为输出 JPEG 帧率 |
| `metrics` | `{cpu_percent,memory_percent,temperature_c}`；CPU 为全机百分比，温度取可读取 thermal zone 最大值，缺失为 null |
| `battery_voltage` | 电压 V 或 null，来自 `/PowerVoltage`；不是剩余电量百分比 |
| `speed_mps` / `max_speed_mps` | 当前巡航限速 / 小车配置上限，m/s，当前上限 0.35 |
| `scan_points` | 最多约 220 个 `[x,y]`，map 坐标下的抽样雷达点 |
| `path` | `{x,y,yaw}[]`，真实 Nav2 规划路径；预览后最多约 1500 个点 |
| `localization` | `{ready,match,amcl_received,match_age_s,covariance}`；match 为 0–1 或 null 的雷达与栅格邻近匹配比例；covariance 为 `{x_m2,y_m2,yaw_rad2}` 或 null，match_age_s 是匹配采样年龄秒 |
| `mission` | 任务状态，见第 5 节 |
| `navigation` | `{ready,planner_ready}`，分别为导航动作和规划动作服务是否就绪；初始化期间不能开始任务 |
| `platform` | `{state:"unconfigured"或"online"或"offline",last_success:unix秒或null,error:字符串或null}` |
| `streams` | `{rviz,camera,rviz_state,rtmp:{rviz,camera}}`；前两个为相对 MJPEG 地址 |
| `error` / `last_error` | ROS/任务错误与控制服务错误，正常为 null |

```json
{
  "imu": {
    "roll_deg": -0.93, "pitch_deg": 0.79, "yaw_deg": 12.4,
    "angular_velocity": {"x": 0.001, "y": -0.001, "z": 0.0},
    "linear_acceleration": {"x": -0.16, "y": -0.13, "z": 9.8}
  }
}
```

IMU 角速度单位 rad/s，加速度单位 m/s²（包含重力）；角度为度。里程计和 IMU 超过 2 秒未更新返回 null。`null` 不应渲染为 0。全局 `sampled_at` 不代表各传感器同时采样。

## 3. 地图、坐标与点击

地图元信息：

```json
{
  "width":800,"height":800,"resolution":0.05,
  "origin":{"x":-20.0,"y":-20.0,"yaw":0.0},
  "frame_id":"map","bounds":[169,269,490,594],"revision":42
}
```

width/height 为像素数，resolution 为米/像素。origin 是 ROS 栅格左下角的世界位姿，yaw 为弧度。bounds 是 PNG 图像坐标的已知区域边界 `[left,top,right,bottom]`（右/下为开区间），用于适应视图。revision 改变后重新获取 PNG。

PNG 左上角为原点、y 向下；ROS grid 左下角为原点、y 向上。图像连续坐标 `(u,v)` → 栅格 `(gx,gy)=(u,height-v)` → 米制 `(a,b)=(gx*r,gy*r)` → 世界：

```
x = origin.x + cos(yaw)*a - sin(yaw)*b
y = origin.y + sin(yaw)*a + cos(yaw)*b
```

若操作整数像素中心，使用 `u+0.5,v+0.5`。画布缩放、平移、留白须先逆变换到 PNG 坐标。目标 yaw 是起点拖向终点的 `atan2(dy,dx)`，范围 `[-π,π]`。不能直接把 RViz 视频像素当成世界坐标。小车前端的“地图”视图使用 `/map` 栅格、TF 雷达点和真实规划路径，与 RViz 的“画面”视图分开。

保存地图对象：`{id,name,created_at,map,saved_pose,area_m2}`。created_at 为带时区 ISO 时间；saved_pose 可空，是保存当时的位姿，不能保证下次开机仍在原地；area_m2 是已知自由栅格总面积。每次保存生成新的 ID，不覆盖旧地图。YAML+PGM 可直接供 Nav2 加载。源码保存 `grid.npy` 供航点检查，不作为公开下载接口。

## 4. 建图接口

| POST 路径 | 请求体 | 成功返回 |
|---|---|---|
| `/api/mapping/start` | `{}` | `{ok:true,mode:"mapping",backup:null或地图对象}` |
| `/api/mapping/restart` | `{}` | 同上，当前建图会先自动保存 |
| `/api/mapping/save` | `{name:"一层大厅"}` | `{ok:true,map:<地图对象>}` |
| `/api/mapping/stop` | `{}` | `{ok:true,mode:"idle"}`，关闭底盘/雷达/建图；不自动保存 |

名称去除首尾空格后为 1–40 字。start 在已建图时返回 `ALREADY_MAPPING`。有运行或暂停的巡航任务时，需先 `/control/stop`。启动采用小车已修复的完整 gmapping launch，自动处理旧 launch，避免同一串口被两套雷达或底盘节点占用。重建/切换导航的备份失败时不会继续丢弃当前建图。

## 5. 定位、路线与巡航

| POST 路径 | 请求体 | 返回/行为 |
|---|---|---|
| `/api/navigation/load` | `{map_id:"map_..."}` | `{ok:true,map,localization:"pending"}`；保存当前建图后切换 Nav2，自动尝试雷达全局定位，不发运动目标 |
| `/api/navigation/auto-localize` | `{}` | `{ok:true,state:"localizing"}`；重新调用 AMCL 全局定位并请求静止扫描更新 |
| `/api/navigation/refine` | `{enabled:true}` | `{ok:true,refine:{…}}`；开关“静止自动校准”：定位就绪后底盘静止时，每 8 s 做一次 ±0.18 m / ±6° 的吸附校准，只在无任务、静止满 6 s、位姿新鲜且吻合度 ≥0.35 时执行，采纳判据与小范围吸附一致；状态随 `localization.refine` 推送 |
| `/api/navigation/localize` | `{pose:{x:1.0,y:0.0,yaw:1.57},snap:true}` | 发布 `/initialpose`，由 AMCL 根据雷达收敛。`snap`（默认 true）先做吸附：点选落在障碍/未知区时移到最近可通行栅格，再在 ±0.35 m / ±12° 内按雷达与地图的吻合度微调；只有提升显著（≥0.06 且 ≥15%）且（结果吻合度 ≥0.35 或提升 ≥0.20）才移动，且候选位姿必须可通行；否则保持点选位置。返回 `{ok:true,state:"localizing",pose:{…吸附后位姿},snap:{applied,free_shift_m,shift_m,shift_deg,score,base_score,samples,reason}}`，`reason` 为 `no_map`/`no_scan`/`weak_match`；微调方向键用 `snap:false` 直接发布不吸附 |
| `/api/navigation/preview` | `{points,mode}` | 用 `ComputePathThroughPoses` 一次规划穿过全部航点（循环含闭合段）并返回路径；起点压在障碍/膨胀区报 `START_BLOCKED`，起点附近雷达点过近或路径不可行报 `NO_PATH`（消息里区分原因）；开头已落在车位 0.40 m 内的目标会先剪掉（首个目标与起点重合会让规划器直接失败） |
| `/api/navigation/start` | `{points:[{x,y,yaw}],mode:"single"}` | `{ok:true,path:[{x,y,yaw}],point_count:1}`；调用 ComputePathToPose，不发运动目标 |
| `/api/navigation/start` | `{map_id,points:[{x,y,yaw}],mode:"multi",speed_mps:0.2}` | `{ok:true,mission}`；向 Nav2 NavigateToPose 提交目标，车辆会运动 |
| `/api/navigation/pause` | `{}` | `{ok:true,state:"paused"}`；取消当前目标，保留航点索引 |
| `/api/navigation/resume` | `{}` | `{ok:true,state:"accepting"}`；重新前往暂停的那个航点 |
| `/api/navigation/speed` | `{speed_mps:0.2}` | `{ok:true,speed_mps:0.2}`；更新 Nav2 SpeedLimit |
| `/api/control/stop` | `{}` | `{ok:true,state:"stopped"}`；优先取消任务并发布零速度；无需等待路线预览的请求锁 |
| `/api/routes/save` | `{name,map_id,points:[{x,y,yaw}],mode,speed_mps}` | `{ok:true,route}`；保存新路线，返回 `{id,name,map_id,points,mode,speed_mps}` |

mode：`single` 点到点恰好 1 个航点；`multi` 1–100 个航点依次运动后结束；`loop` 2–100 个航点循环，最后回到第一个，直到暂停或停止。循环预览包含闭合路径。yaw 指到达航点时的车头朝向。路线与地图 ID 绑定，启动时必须和当前加载地图一致。

速度必须为有限数字，当前允许 `[0.05,0.35] m/s`。0 不是停止指令（Nav2 SpeedLimit 中 0 表示解除限速）。停止必须用 `/control/stop`。限速使用绝对速度、`percentage:false`，定期重发给 Nav2；底盘角速度及转弯约束继续使用现有 mini_akm 配置。

所有坐标必须是有限数字、在地图内，并处于已知自由栅格；未知、障碍区域均拒绝。该检查不是完整车身碰撞检查，Nav2 costmap/规划器仍会检查可通行性。预览可能返回 `NO_PATH`，不要以两点直线替代为真实路径。

定位：自动定位不驱动车辆旋转或平移，约 30 秒静止更新后仍未收敛会提示人工定位。用户可在“地图”视图选择人工定位并拖动设置车头方向。`localization.ready` 要求 AMCL 位姿、近期 TF/雷达、匹配比例≥0.45、x/y 方差<0.5 m²、yaw 方差<0.5 rad²。match 使用约 0.18 m 障碍邻域，是辅助指标，不是定位准确率保证。人工位姿提交成功不等于已经定位；以更新后的 ready 为准。

任务对象：

```json
{"state":"running","index":0,"cycle":0,"points":[{"x":1,"y":0,"yaw":0}],"mode":"single","distance_remaining":0.8}
```

state：idle、accepting、running、pausing、paused、stopping、stopped、completed、failed。index 从 0 开始；cycle 是已经完成的循环数；distance_remaining 为当前航点剩余距离 m，可 null。达到一个点且 Nav2 返回 SUCCEEDED 后才提交下一点；拒绝或失败立即结束任务。暂停/停止等待取消和目标终态，迟到的目标接受也会取消。取消无法确认时关闭导航进程，拒绝直接恢复，需重新加载地图。运行中持续丢失定位/雷达/里程计会自动结束任务。

典型流程：加载地图 → 等待定位/人工定位 → 编辑航点 → 路线预览 → 设置速度 → 开始 → 通过 WS 观察终态。前端刷新不会重发运动目标。服务和浏览器自启也不会自动开始建图或巡航。

主要错误码：`MAP_UNAVAILABLE`、`MAP_NOT_FOUND`、`INVALID_MAP_ID`、`INVALID_NAME`、`INVALID_WAYPOINTS`、`INVALID_POSE`、`OUTSIDE_MAP`、`POINT_BLOCKED`、`MAP_MISMATCH`、`NOT_NAVIGATING`、`NOT_LOCALIZED`、`NAV_NOT_READY`、`PLAN_REJECTED`、`NO_PATH`、`MISSION_ACTIVE`、`NOT_RUNNING`、`NOT_PAUSED`、`PROCESS_CONFLICT`、`LAUNCH_FAILED`、`CANCEL_UNCONFIRMED`、`NAV_SHUTDOWN`、`ROS_TIMEOUT`。

## 6. 视频与 RTMP

| 通道 | 浏览器直接观看 | RTMP 设置字段 |
|---|---|---|
| RViz | `/api/streams/rviz.mjpeg` | `rviz_rtmp_url` |
| 摄像头 | `/api/streams/camera.mjpeg` | `camera_rtmp_url` |

MJPEG 响应类型 `multipart/x-mixed-replace; boundary=frame`，可直接 `<img src="...">` 嵌入；8 FPS 目标输出，实际以 camera.fps/网络负载为准。未就绪通道不伪造图像，客户端应参考独立状态并显示离线。

RViz 运行在小车专用 Xvfb `:99`，采集这个独立画面，避免把显示前端的桌面再推回前端。摄像头订阅 `/camera/color/image_raw`，启动 Astra RGB 驱动，不启动不必要的深度点云处理。

可在小车右上角设置页保存：

```http
POST /api/settings/save
```
```json
{
  "platform_url":"http://平台IP:端口",
  "platform_token":"由平台分配的设备令牌",
  "rviz_rtmp_url":"rtmp://推流服务器/live/car01_rviz",
  "camera_rtmp_url":"rtmp://推流服务器/live/car01_camera"
}
```

未填写平台或 RTMP 地址时不发送。RTMP 输出 H.264/yuv420p、无音频、约 1200 kbps/路、GOP 约 2 秒。小车是推流客户端，不提供 RTMP 接收服务器。平台需要自行接收并转为浏览器可播放的 WebRTC/HLS/HTTP-FLV；浏览器不能直接播放 rtmp:// URL。两路推流目标可不同。`streams.rtmp` 的 disabled/starting/running/failed 表示本地编码进程状态，running 不等于平台已经收到或播放。编码进程退出后，源画面正常时约 10 秒后自动重试。错误日志分别为 `runtime/logs/rtmp-rviz.log`、`rtmp-camera.log`。

`GET /api/config` 返回 device_id、platform_url、rviz_rtmp_url、camera_rtmp_url、telemetry_interval_s、platform_token_set。POST 未带的字段保持原值；空字符串清除对应地址或令牌。device_id、端口、ROS 工作空间等部署配置在 `config.local.json` 中修改后重启服务，不支持从设置接口任意更改。

## 7. 小车向现有平台上报

`backend/uplink.py` 已按平台现有 device gateway HTTP 格式实现。这里只准备小车发送端，没有更改平台接收代码或页面。设备令牌和目标地址由用户后续配置。

注册请求：

```http
POST {platform_url}/api/devices/register
X-Device-Id: mumai-car-01
X-Device-Token: <平台分配令牌>
Content-Type: application/json
```
```json
{
 "schemaVersion":"1.0","deviceId":"mumai-car-01","bootId":"当前服务会话UUID",
 "appVersion":"1.0.0","adapterVersion":"ros2-humble-1",
 "host":{"kind":"robot","os":"linux"},
 "capabilities":{"mapping":true,"navigation":true,"telemetry":true,"video":["mjpeg","rtmp"]}
}
```

随后约每秒发送：

```http
POST {platform_url}/api/device-events/batch
X-Device-Id: mumai-car-01
X-Device-Token: <平台分配令牌>
Content-Type: application/json
```
```json
{
 "events":[{
  "schemaVersion":"1.0","type":"device.telemetry","deviceId":"mumai-car-01",
  "bootId":"当前服务会话UUID","messageId":"本条消息UUID","seq":1,
  "sentAt":"2026-09-14T12:00:00+00:00",
  "payload":{"schema_version":"1.0","device_id":"mumai-car-01","simulated":false,"mode":"mapping","velocity":{"linear_mps":0.0,"angular_rps":0.0},"metrics":{"cpu_percent":30.2,"memory_percent":22.0,"temperature_c":60.1}}
 }]
}
```

payload 实际包含第 2 节完整状态，省略大体积 `scan_points`、`path`、`imu_history`；上例为节选。速度、IMU、CPU、温度、电压、传感器状态、任务、定位、视频状态都在该 payload。平台可通过 GET/WS 另取地图与几何数据。streams 里的地址相对小车根地址，不是平台自己的根地址；平台若跨源嵌入应配置反向代理。

平台确认格式（支持外层 `data` 包裹）：

```json
{"accepted":["本条消息UUID"],"duplicated":[],"rejected":[]}
```

只有 messageId 出现在 accepted/duplicated 且无 rejected 时，小车显示平台已连接。HTTP 成功但缺少确认不会误判为在线。断线按 1、2、4…30 秒退避重注册，重连后上传最新状态；没有离线历史补传队列。seq 在每个进程内递增，bootId 在服务重启时更换，平台去重应使用 deviceId+bootId+messageId。

平台适配建议：独立判断设备 WS/遥测新鲜度、地图、位姿、RViz、摄像头；分别显示离线。调用运动控制接口需保留 command ID，并将接收状态和执行终态分开。当前小车不会主动轮询平台任务队列；平台下发控制可由平台后端调用本文件第 4、5 节的已实现 API。

## 8. 电池与底盘补充接口

`GET /api/battery` 和 `GET /api/chassis` 分别返回下面的 battery、chassis 对象；同样的对象已包含在 `/api/state`、WS 状态和平台 telemetry payload 中。

```json
{
 "battery":{
  "state":"online","voltage_v":10.85,"age_s":0.12,
  "percentage":null,"charging":false,"charging_current_a":0.0,"bms":null
 },
 "chassis":{
  "state":"online","model":"mini_akm","drive_type":"ackermann","age_s":0.05,
  "odometry":{"pose":{"x":0.0,"y":0.0,"yaw":0.0},"linear_mps":0.0,"lateral_mps":0.0,"angular_rps":0.0,"frame_id":"odom","child_frame_id":"base_footprint"},
  "commanded_velocity":{"linear_mps":0.0,"angular_rps":0.0},"command_age_s":0.1
 }
}
```

电压来自 `/PowerVoltage`（Float32，V）；充电标志来自 `/robot_charging_flag`（Bool）；充电电流来自 `/robot_charging_current`（Float32，A）。各字段 5 秒未更新返回 null。并非所有固件都会实际发布所有字段，缺失不等于未充电或电流为零。

`/battery_state`（sensor_msgs/BatteryState）是预留标准 BMS 输入。只有收到合法的 0–1 percentage 才换算为 0–100%，不使用电压线性估算。bms 对象可含 percentage、current_a、temperature_c、capacity_ah、charge_ah、power_supply_status，非有限值置 null。当前底盘已确认提供电压，未确认提供真实剩余容量。

底盘 odometry 来自原始 `/odom`，超过 2 秒不更新返回 null；与导航融合里程计 `/odom_combined` 分开。commanded_velocity 来自 `/cmd_vel`，是控制指令，不代表实测速度；超过 2 秒返回 null。pose 使用 odometry 自身 frame_id，不能当作 map 坐标。界面显示底盘在线状态与 x/y 里程计位置。编码器计数、电机电流、转向角未在当前适配中伪造。

摄像头状态新增 `camera.size:{width,height}`，表示输出图像尺寸；前端按其比例显示，默认 4:3，不裁剪画面。

建图页“重置地图”对应 `/api/mapping/restart`：先持久化当前地图，再关闭旧建图并重新启动。按钮更名不改变已有 API。

## 2026-09-15：航点改为仅位置

`POST /api/navigation/preview`、`POST /api/navigation/start`、`POST /api/routes/save` 的 `points` 元素统一为 `{"x":1.2,"y":0.8}`，单位米、map 坐标系。不需要也不使用 yaw；兼容旧客户端传入 yaw，但服务忽略它。路线列表及任务状态中的 points 只返回 x/y。人工定位接口的 pose 仍需 yaw（机器人定位姿态），不受此更改影响。

服务内部依据相邻线段自动生成目标切向，拐点取进出方向的角平分方向，首尾按相邻段处理，循环模式考虑闭合段。方向仅用于内部 Nav2 PoseStamped，不是用户航点属性。预览和任务采用相同计算。

Smac Hybrid 的 DUBIN 前向搜索与 MPPI Ackermann 控制继续遵守配置的最小转弯半径 0.35 m。实际曲线由代价地图和障碍物约束决定；此值是当前软件配置下限，并非本轮重新实测的机械极限，也不保证每个转弯都采用最小半径。狭窄区域可能无前向可行路线，不会因此自动倒车。

## 连续巡航相关配置（`config.local.json` 可覆盖）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `cruise_arrival_radius` | 0.08 | 到点判定半径：行为树的经过半径与终点 goal_checker 都用它，规划器容差取 2/3（≤0.25 m）|
| `cruise_lookahead_m` | 2.5 | 批次窗口按距离补足（米）：密集航点（录制 10 cm）不会每几个点就停一次 |
| `cruise_lookahead_max_points` | 40 | 批次窗口点数上限，限制单次规划量 |
| `cruise_relocalize` | true | 航行中定位守护：吻合度 < `cruise_relocalize_match`(0.55) 持续 2 s 就小窗口吸附重锚 AMCL；累计 `cruise_relocalize_max`(4) 次仍不达标则安全停车。状态随 `localization.relocalize` 推送 |
| `skip_missed_points` | true | 航点被越过却没进到达半径时跳过它，去下一个点修正（避免绕回去） |
| `cruise_lookahead` | 4 | 每批下发的目标点数：窗口内航点依次穿过（0.40 m 剪枝）、整批走完才推进游标。`1` = 每个航点都停（旧行为），`0` = 尽可能连续（multi 全部剩余 / loop 一圈减一段） |
| `refine_idle*` | 见配置样例 | 静止自动校准 |
| `rviz_size` / `rviz_chrome` / `rviz_follow` | 见配置样例 | 实时地图推流与视角 |

启动巡航要求相邻航点（循环含闭合段）间距 ≥ 0.30 m，否则报 `POINTS_TOO_CLOSE`；
起点压在障碍/膨胀区上会直接报 `START_BLOCKED`，避免进入“导航未完成”这种含糊结果。

## 切换地图与建图备份

`POST /api/navigation/load` 支持 `save_current`：

| 取值 | 行为 |
| --- | --- |
| 省略（默认） | **自动判断**：处于建图模式且相对上次保存有实质改动（栅格差异 > 1%）才自动备份为“切换前备份 HH:MM”，否则直接切换、不再打扰 |
| `true` | 强制先备份当前建图再切换 |
| `false` | 不备份，直接切换 |

返回体带 `backup`（本次备份的地图对象，未备份为 `null`）。
状态推送新增 `mapping` 字段：`{saved, changed, diff_ratio, saved_name}`——界面据此决定“加载地图”时是否弹窗，
弹窗提供 **取消 / 不保存，直接切换 / 保存并切换** 三个选项。

## 航迹记录与障碍禁区

## 相机标签定位（默认关闭）
