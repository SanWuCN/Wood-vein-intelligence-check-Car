# 预览与巡航入口报错修复

2026-09-15，小车 192.168.31.221。

## 原因

12:04–12:05 的 systemd 日志确认，`RosBridge.preview()` 与 `RosBridge.start_mission()` 都在调用 `validate_waypoints()` 时抛出 `NameError: name 'validate_waypoints' is not defined`。该函数仍存在于 core.py，但 ros_bridge.py 的导入列表漏了它。异常被 HTTP 中间件转换成 500，前端只显示“操作失败，请检查服务日志”。

这次故障发生于提交规划/导航目标之前，不是截图里约 98% 的定位匹配率导致。

## 修改与验证

- 仅补回 backend/ros_bridge.py 的 validate_waypoints 导入；保留其余现有代码、地图、路线和配置。
- tests/test_nav_validation.py 新增 4 项回归：循环预览闭合、预览拒绝障碍点、合法启动请求进入模拟发送器、未知区航点不能进入发送器。
- 新增 4 项在修复前全部复现 NameError，修复后全部通过；车机 ROS 环境全部 33 项测试通过。
- 测试直接调用实际桥接类的方法，但使用内存中的假对象；没有创建 ROS 节点，导航发送与限速发布均替换为 Mock。没有调用生产 navigation/start 或 resume，没有实车行驶测试。
- 旧文件备份：`/home/wheeltec/mumai-console/runtime/backups/nav-import-20260915/ros_bridge.py`。
- 已部署并重启 mumai-console.service，健康状态正常。
- 12:15 验证：mode=idle，mission.state=idle，linear_mps=0，active_map_id=null，导航和规划动作服务未启动；未发现 wheeltec_nav2 launch 或 Nav2 容器进程。下一次现场使用需要重新加载地图和定位。
