# 连续巡航（看重后续航点）与到点容差

日期：2026-09-15。需求两点：路径规划要能“看多一个点”，在拐弯处就按整段路规划；到航点的判断别那么准，
大概进范围就算到达、继续开向下一个，避免过冲后绕大圈回头。

## 改了什么

**1. 一次规划穿过多个航点（连续巡航）**

- 巡航任务由“完成一个点再下发下一个点”改为按**目标窗口**下发 `NavigateThroughPoses`：
  一次把窗口内的航点交给 Nav2，行为树按 1 Hz 重新规划整段路径，因此规划器在驶向当前航点时已经看到了后面的航点，
  拐角处直接按整段曲率规划，不再“到点才对下一个点做规划”。
- 窗口内航点无需停车：行为树用 `RemovePassedGoals radius=0.40` 剪枝，进入 0.40 m 就算经过，直接驶向下一个。
- 窗口大小 `cruise_lookahead`（默认 4）：决定小车每隔几个航点才会停一次，同时限制单次规划量。
  `1` = 每点都停（旧行为），`0` = 尽可能连续（multi 一次下发全部剩余、loop 取一圈减一段）。
- 循环模式窗口**必须小于一圈**：控制器每个周期都拿“路径终点”和车位比较，终点若正好落在车位
  （循环闭合处）会被立刻判为到达，任务会空转。环状取点同时天然覆盖闭合段，不需要再复制首点。
- 进度：用动作反馈的 `number_of_poses_remaining` 推进游标（只前进不回退），圈数由游标推算；
  “剩余距离”由本窗口剩余路径 + 后续航点直线距离合成，不再只反映当前窗口。

**2. 到点判定放宽、取消车头朝向要求**（`navigation_profile.apply_forward_profile`，写入 `runtime/navigation.yaml`）

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `goal_checker.xy_goal_tolerance` | 0.40 m | 进范围即算到达 |
| `goal_checker.yaw_goal_tolerance` | π | 终点不再要求车头朝向对齐 |
| `GoalAngleCritic.enabled` | false | 控制器不再为了对朝向而绕圈 |
| `motion_model_for_search` | DUBIN / 最小转弯半径 0.35 m | 前向、曲率约束 |
| `vx_min` / `enforce_path_inversion` | 0.0 / false | 不倒车 |

**3. 两个实际会踩到的坑（本次实机排查发现）**

- **相邻航点太近**：窗口终点可能落在车位容差内，会被立刻判到达并跳过后续航点。
  现在 `validate_waypoints` 要求相邻航点（循环含闭合段）间距 ≥ 0.50 m，报 `POINTS_TOO_CLOSE`。
- **起点压在障碍上**：规划器会以 `Starting point in lethal space` 失败，界面只看到“无可行路径”。
  现在先做 `start_conflict` 静态判定（车位 0.25 m 内有占据格）报 `START_BLOCKED`；
  若失败时车位 0.40 m 内有 ≥6 个雷达点，提示改为“起点附近有障碍，请把车移开或清理代价地图”。
- **预览的首个目标与车位重合**会让规划器直接 ABORTED（实测 status=6、0 路径点），
  预览前先剪掉开头已在容差内的目标（执行时由行为树的 RemovePassedGoals 负责）。

## 验证（未发运动目标）

- 测试：本机 68 项通过（20 项需 ROS 跳过），小车 ROS 环境 **68 项全部通过**。
  新增覆盖：窗口线性推进/环状取点/一圈内窗口、游标只前进、圈数推算、剩余里程、
  最小间距校验、起点冲突判定、车位附近雷达点数、剪枝规则。
- 实机参数（`ros2 param get` 读运行中的服务）：`goal_checker.xy_goal_tolerance=0.4`、
  `yaw_goal_tolerance=3.14159`、`GridBased.motion_model_for_search=DUBIN`、`FollowPath.vx_min=0.0`；
  生成的 `runtime/navigation.yaml` 指向 `continuous_navigation.xml` 与 `forward_navigation.xml`，两个 BT 均为合法 XML。
- 连续规划实测（只调规划动作，不动车）：用户 10 点循环路线，从**小车实际位姿**一次规划穿过全部航点并闭合，
  得到 241–244 个路径点、全长 17.5 m、耗时 0.7 s；**10 个航点距路径最大偏离 0.03 m**（容差 0.40 m）。
- 分段可行性：10 段中 9 段单独规划 OK；把起点自身当作首个目标的退化输入会 ABORTED，已由剪枝规则覆盖。

## 边界

- 未执行实车巡航：本次只做参数、规划与逻辑验证，没有下发运动目标。首次实车建议先用 2–3 个航点的短路线，
  确认“过点不停车、不绕圈”，再放开整条循环。
- 窗口越大单次规划越重（1 Hz 重规划）；航点很多时建议 `cruise_lookahead` 不超过 6–8。
- 起点被**实时障碍层**（雷达临时看到的障碍）判为致命时，静态地图判定查不出来，会退化为“无可行路径 +
  起点附近有障碍”的提示；把车移开一点或清理代价地图即可。
